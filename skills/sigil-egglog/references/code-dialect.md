# Code claims dialect

This is the code profile for a whole-file implementation interpreter. The
prepared `rows.md`, `examples.md` and `rejected.md` are binding for row shapes
and accepted names; this skill supplies language background. Load
`sigil-understand` for the meaning of the presented design context.

Return only `element`, `realizes`, `act`, `measure` rows as flat calls with
quoted string literals, one row per line in a plain-text egglog file. Numbers
are quoted strings too. No nested calls, arithmetic, variables, rules,
declarations, JSON, markdown fences or prose belong in the artifact. A `rule`,
`command`, `schedule`, `ruleset` or `run` is executable language, never data.

Admission is by whole file. Executable forms or invalid data refuse that file;
empty answers or answers with no element leave it unread. Retain every observed
element even when it has no design mapping. Refusal is the compiler's decision;
the host cannot repair, omit or replace the child's rows.

Observation and mapping are separate. Component realization means membership
supported by an in-scope design claim accounting for that element's behavior.
A Tag realization means delivery and supplies no Component membership by itself.
File placement, names, nearby elements and annotations establish no mapping.
A test maps design names it exercises but never answers a production promise
or supplies production membership, delivery or ownership.

Follow the prepared code guidance, not the design-row profile. Do not import
design unit rules or return design claim rows. No Turtle is parsed or returned.
